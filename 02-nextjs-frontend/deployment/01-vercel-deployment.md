# Vercel 部署：构建、环境、验证与回退

先修：能在本地运行 Next.js，知道 Git 提交和环境变量。目标是把一个已有应用发布为可验证的预览，再建立生产发布流程。本章不预设任何付费套餐额度，也不包含对真实账号执行部署。

## 1. 从可重复本地构建开始

```sh
npm ci
npm run build
npm run start
```

先确认 package.json 的脚本存在，锁文件已提交。Next、React、React DOM、类型包与 ESLint 配置应使用兼容版本，不能从不同年代的示例各复制一个版本号。部署排错时记录实际锁定版本与 Node 版本，而不是仅写“最新”。

本地构建成功后，检查首页、动态页面、错误页和必要服务连接。需要登录的功能应使用测试账号；构建成功只证明生成了产物，不证明线上环境变量、数据库和回调地址正确。

## 2. 导入项目时明确四项设置

| 设置 | 如何判断 |
|---|---|
| 仓库与生产分支 | 确认哪个分支的提交会触发生产发布 |
| Root Directory | 单仓库应用通常是根目录；monorepo 选择真正应用目录 |
| Framework Preset | 使用 Next.js 适配，优先保留识别出的构建流程 |
| 环境变量 | 分别配置 Development、Preview、Production 的值 |

Next.js 项目通常不需要手写旧式 builds/routes 把所有请求重定向到一个函数。先采用平台的框架适配，只有明确需求时才增加 vercel.json。平台环境与分支规则见 [Vercel Environments](https://vercel.com/docs/deployments/environments)。

## 3. 环境变量与外部服务必须成套隔离

Preview 应连接测试数据库、测试支付凭证和测试邮件服务。仅把网站域名换成预览域名，不会自动隔离后端数据。

```dotenv
# .env.example：只记录变量名和非敏感说明
DATABASE_URL=
AUTH_SECRET=
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

真实值在平台环境设置或本地忽略的文件中管理。AUTH_SECRET 只是示例变量名，是否被读取取决于认证库和代码，不能通过“配置了一个变量”推断功能已经接入。

NEXT_PUBLIC_ 值可能进入浏览器构建产物。修改环境变量后，应按平台流程重新部署使用新值；已经构建的公开值不会因服务器环境改动而自动变化。第三方 OAuth 回调地址也要包含对应环境的实际地址。

## 4. 先验证预览再提升生产

先提交到开发分支并检查预览部署的构建日志。打开实际预览地址完成一条业务路径，例如登录、创建测试记录、刷新后确认记录存在、退出登录。

随后检查：未登录是否被拒绝、404 是否合理、图片与字体是否成功、浏览器是否出现服务器密钥、服务端错误是否可追踪。记录验证的部署 URL 和提交标识，避免把另一个版本的结果当成当前结果。

预览环境保护、团队权限和发布入口因项目配置而异；访问不了预览不一定是应用崩溃，先区分平台访问控制与应用认证。

## 5. 数据库迁移不是普通构建副作用

多个分支和重复构建可能并发运行。不要在任意预览构建时无条件对生产数据库执行迁移。迁移应有明确环境、顺序、权限与失败策略。

扩展—迁移—收缩是一种常见做法：先增加兼容字段，部署能同时理解旧新数据的代码，回填并验证，最后移除旧字段。这样旧版本在回退时还有机会正常工作。删除列或改变语义之后，回退网页代码不会自动恢复数据。

## 6. 部署后观察与回退

为关键操作记录请求 ID、部署版本、状态码、耗时和可公开的错误类型。平台日志、浏览器异常、数据库指标应能对应到同一时间段。不要把“函数返回 200”当作业务成功的唯一证据。

发现回归时，先确认受影响功能与版本，再使用平台支持的回退或重新部署流程。环境变量、数据库迁移、外部任务和已发送通知都可能独立于代码版本变化，应在发布记录中列出。平台的部署管理入口见 [Deployments](https://vercel.com/docs/deployments)。

函数时限、区域、连接数与费用依平台和套餐变化；需要时查当前文档与项目设置。把长任务改成队列与后台处理，比单纯不断提高请求时限更容易控制重试与状态。

## 7. 练习与完成标准

部署一个只连接测试数据的预览。故意缺少一个必要环境变量，观察构建期或运行期报错，再补齐并重新部署。记录为什么错误发生在那个阶段。

第二次提交加入一个可见版本标识，验证新版本后回退到前一版本。验收材料包括两次提交、部署记录、业务验证步骤和数据是否保持兼容的说明。本地阅读本文或执行 build 不算已经完成线上部署演练。

自测：Preview 默认不会写生产数据吗？取决于实际服务配置。回退一定撤销数据库修改吗？不会。next.config 的 env 适合放密码吗？不适合，它可能被内联进客户端代码。
