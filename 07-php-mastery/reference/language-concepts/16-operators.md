# 运算符全表与优先级

> **模块**: `07-php-mastery` | **类型**: 字典条目（可独立查阅，按主题准备前置知识，支持任意跳入查阅）

## 📌 定义

PHP 运算符速查：算术、字符串、赋值、比较、逻辑、位运算与错误控制。行为说明需结合所用 PHP 版本验证；比较语义细节见弱比较条目。

## 📖 分类速查

### 算术

| 运算符 | 说明 |
|--------|------|
| `+ - * /` | `/` 非整除时得 float（`7/2 === 3.5`） |
| `%` | 取模**符号跟随被除数**：`-7 % 3 === -1`，`7 % -3 === 1`（预期）；整除商用 `intdiv(7, 2) === 3`、`intdiv(-7, 2) === -3`（向零取整） |
| `**` | 幂，**右结合**：`2 ** 3 ** 2 === 512`，`(2 ** 3) ** 2 === 64`（预期） |

### 字符串

```php
$full = 'Dev' . 'Quest';          // . 拼接
echo "n: " . 1 + 2;               // "n: 3"（PHP 8 起 . 优先级低于 + -，先算 1+2 再拼接；PHP 7 结果是 2）
$name = 'PHP';
$ver  = 8.5;
echo "$name $ver";                // 简单插值：变量、数组无引号键 $arr[k]、对象属性 $o->p
echo "{$amount}00";               // 复杂插值（花括号）：$arr['k']、$o->m() 等表达式（预期均可用）
```

### 赋值与合并

```php
$a ??= $b;         // null 合并赋值：$a 为 null 时才赋值（预期：存在值时不覆盖）
$b = $x['k'] ?? 'default';   // ?? 链式安全：不存在的多维键不产生告警（预期）
$c = $opt ?: 'fallback';     // Elvis：取真值否则回退（预期 "" → fallback）
```

### 比较

`==`/`===`、`!=`/`!==`、`<=>`（太空船：小于返回 -1、等于 0、大于 1；字符串的比较还受 numeric string 规则影响，非数字文本通常按字节比较，预期 `"a" <=> "b" === -1`）——完整规则见 **[弱比较与强比较](./13-weak-comparison.md)**。

### 逻辑

| 运算符 | 说明 |
|--------|------|
| `&&` `\|\|` `!` | 高优先级版 |
| `and` `or` `xor` | **优先级低于 `=`**：`$r = true and false;` 预期 `$r === true`；`$s = false or true;` 预期 `$s === false` |

### 位运算

```php
var_dump(5 & 3);    // 1    AND
var_dump(5 | 3);    // 7    OR
var_dump(5 ^ 3);    // 6    XOR
var_dump(~5);       // -6   NOT
var_dump(1 << 4);   // 16   左移
var_dump(256 >> 4); // 16   右移
```

### 错误控制 @

```php
$value = @file_get_contents('/maybe/missing');
```

- @ 抑制该表达式产生的诊断信息；自定义 `set_error_handler` 仍会被调用（php.net 明确说明），错误可通过 `error_get_last()` 取回。
- **PHP 8.0 起致命错误不再被 @ 吞掉**：`@unknown_function()` 依旧 Fatal（预期退出码 255）；php.net 原文："Prior to PHP 8.0.0, it was possible for the @ operator to disable critical errors that will terminate script execution."
- PHP 8.0 起自定义错误处理器内 `error_reporting()` 在 @ 场景不再返回 0，而是返回致命级别位掩码（`E_ERROR|E_CORE_ERROR|E_COMPILE_ERROR|E_USER_ERROR|E_RECOVERABLE_ERROR|E_PARSE`）。

## ⚠️ 常见陷阱

- ❌ **`$result = getVal() or die('failed');` 后以为 `$result` 是布尔**：赋值先发生，`or` 只影响整条语句的短路。
- ✅ 显式写：`$result = getVal(); if ($result === false) { ... }`；避免 `or die` 风格。
- ❌ **`"合计: " . $a + $b`**：PHP 8 下语义变为拼接 `($a + $b)`，PHP 7 下完全不同——版本间结果不可移植。
- ✅ 拼接表达式一律加括号：`"合计: " . ($a + $b)`。
- ❌ **用 `%` 处理负数当"数学取模"**：结果符号跟随被除数（`-7 % 3 === -1`），不是数学模运算。
- ✅ 对正整数模数 b，先算 r = a % b，再仅在 r < 0 时加 b；还要拒绝 b <= 0。
- ❌ **`@` 当异常防护网**：它只压诊断，压不住异常与致命错误，还会掩盖真实问题。
- ✅ 用 try/catch 与明确的错误分支；@ 仅限第三方库遗留告警等确需静音的窄场景。
- ❌ **`$x = 1 ? 2 : 3 ? 4 : 5;` 不加括号**：8.0 起是编译期 Fatal，try/catch 都包不住。
- ✅ 永远写全括号：`$x = (1 ? 2 : 3) ? 4 : 5;`。
- ❌ **字符串插值里写 `"$arr['k']"` 或 `${var}`**：前者语法错误，后者已弃用。
- ✅ 简单键写 `"$arr[k]"`，复杂表达式写 `"{$arr['k']}"`。

## 优先级决定结合方式，不保证求值先后

前置是赋值和函数调用。`$ok = true and false` 先把 true 赋给变量，而 `$ok = true && false` 赋入 false；可读性更好的写法是给复合表达式加括号。优先级表不等于操作数求值顺序，别在同一复杂表达式里反复修改同一个变量并依赖执行先后。

`??` 判断未设置或 null，`?:` 按真假性判断；`&&` 和 `||` 返回布尔值，不能照搬其他语言中返回某个操作数的习惯。字符串按位运算和整数位运算也有不同路径，处理二进制协议时应明确操作数类型。

**练习**：分别运行上述 and/&& 两种赋值并输出结果；再对 -7、0、7 在正模数 3 下规范化余数，预期为 2、0、1。不要简单给所有余数加模数，否则 0 会错误地变成 3。@ 不会将失败结果转换成成功，也不会替你检查 false。
