# 全库验证与修补记录

本轮已扫描知识库现行 Markdown 围栏，并修补已确认的代码错误和验证器误判。提取器排除 refactor-archives 历史归档、.git、.remember 与 node_modules，不将历史重构材料作为现行教学代码验收。**扫描完成不代表所有片段都能独立运行，也不代表全部框架项目已经构建成功。** 本报告将语法解析、带上下文的编译、实际执行分开记录。

## 已确认并修补的问题

- Go：补全 channel、errors、io/bufio、slices/maps 示例；纠正代码与配置混用的围栏；修复交互程序在 EOF 后反复输出的问题。空输入、正常输入、错误输入、长 Unicode 输入和加法路径已复验，HTTP 示例以真实请求验证健康检查、用户响应与方法拒绝。
- 前端：修正 105 个 JSX 语言标签，分离混在同一围栏中的 CSS、JSON 和安装命令，补齐实际 JSX 根节点与组件结构。TanStack 速查示例使用真实导入和 API，移除为了消除报错而虚构的声明；保留框架类型诊断。
- Swift / Kotlin：将会造成语法错误的占位写法改成具体实现，补上真实变量、分支、初始化和标准库导入。平台依赖片段保留其环境要求。
- PHP / Python / Java / Node.js：修复提前关闭 PHP 标签、重复导入、不完整表达式、裸控制语句、混入源代码的交互提示符、错误类结构及示例输入输出不一致等问题。
- 检查工具：代码块独立作用域、真实退出码、工具缺失状态、完整诊断、跨平台路径和按内容哈希匹配证据均有回归检查。没有新增短哈希豁免来掩盖失败。

逐语言复核记录：[Go](../go-review.md)、[Java](../java-review.md)、[Rust](../rust-review.md)、[Python](../python-review.md)、[Kotlin](../kotlin-review.md)、[Swift](../swift-review.md)、[PHP](../php-8.5-review/PHP-8.5-STATIC-REVIEW.md)。其中部分表格记录修补前快照；当前状态以本目录合并报告为准。

## 证据与复现

[evidence.tar.gz](evidence.tar.gz) 保存当前清单、各轮清单与结果、工具摘要、运行脚本和大小适中的命令日志。[evidence-inventory.json](evidence-inventory.json) 列出所有证据文件的 SHA-256、大小和是否打包。早期 Go 输入循环产生的超大命令日志未放进 Git，完整原件保留在工作区旁的 verification-lab 中；因此该压缩包不是所有原始 stdout 的完整副本。对应问题已经修复并以 go-recheck 的独立运行日志复验。

合并证据必须同时匹配文件路径、语言和清单正文的完整 SHA-256；内容变化后旧结果不会自动沿用。复现时先用 extract_blocks.py 提取清单，再用 merge_evidence.py 的 --manifest、多个 --run 和 --output 参数合并，--run 的顺序见 summary.json。TS/JS 解析使用 TypeScript 5.9.3 和 Node 24。各语言工具版本与命令保存在证据中；运行层在无网络、无凭证、资源受限的临时容器完成。

操作说明见 [验证器说明](../../../code-block-verify/README.md)。自动 push 检查负责链接、标题锚点、围栏闭合和检查器回归；跨语言全量检查保留为手动 workflow_dispatch，并默认关闭代码执行。此前流水线修复提交 2ed2d05 的 [自动检查已通过](https://github.com/x-rush/dev-quest/actions/runs/35331523407)，这不代表手动全量检查通过。

## 后续内容验收标准

对待复核项，应逐技术栈建立带真实依赖的最小项目，再把片段关联到文件、前置声明和运行步骤；Android、Apple 平台与外部服务分别使用对应环境。故意错误的例子应同时写出预期错误和正确版本。不得仅凭缺少上下文就删除示例，也不得把真实代码改成文本或伪造 API 来让检查变绿。

教学质量仍需逐篇审阅：术语解释、使用动机、最小例子、输出说明、边界和练习不能由语法检查代替。本轮结果提供可追踪的技术验证底稿，而非对全库教学完整性的最终认证。
