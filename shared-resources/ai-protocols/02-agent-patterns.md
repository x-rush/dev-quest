# Agent 模式语言（框架无关）

> **形态说明**：本篇沉淀 Agent 工程的**模式层**——这些模式独立于任何框架（OpenAI Agents SDK / LangChain / Claude Agent SDK / Vercel AI SDK 等）。框架只是模式的某种封装，框架本身过时风险高，不列入本仓收录；理解模式后，任何框架文档都只是"查表"。

## 一、Agent 的最小定义

Agent = **LLM + 工具循环**：模型决定调用什么工具 → 环境执行 → 结果回填上下文 → 循环，直到模型判定任务完成或触发停止条件。一切 Agent 框架都是对这个循环及其周边设施的工程化。

## 二、核心模式

### 1. 工具调用循环（Tool-Use Loop）
最基础模式。工具描述（名称/参数 schema/说明）进入上下文，模型输出结构化调用。**不变量**：工具描述是模型行为的唯一依据——描述质量直接决定调用质量；工具描述属不可信输入（与 MCP 安全原则一致）。

### 2. 计划-执行（Plan-then-Execute）
先产出显式计划（任务分解），再逐项执行。适用于任务依赖清晰、可预先分解的场景。**权衡**：显式计划可审查、可恢复；但环境反馈会使预计划失效，需配合重规划。

### 3. 反思与自校验（Reflection）
执行结果回灌后让模型批判性检查（编译错误、测试失败、空结果），再修正。ReAct（Reason+Act 交替）是该族的经典形态。**不变量**：反馈信号必须真实（编译器/测试器输出优于模型自我评价）。

### 4. 多智能体编排（Orchestrator-Worker）
主 Agent 分派子任务给专长子 Agent，汇聚结果。适用于上下文隔离（子任务细节不污染主上下文）与并行化。**代价**：通信即开销，子 Agent 无共享记忆时信息会丢失——需显式设计交接物（结构化报告而非对话续传）。

### 5. 记忆分层（Memory Hierarchy）
- **工作记忆**：当前上下文窗口（稀缺资源，需上下文工程管理）
- **情景记忆**：会话外持久化（文件/数据库，按需检索）
- **语义记忆**：知识库（RAG 检索增强）
**不变量**：上下文窗口是零和资源——塞入的每段内容都在挤占其他内容；检索质量优于堆料。

### 6. 护栏与人工确认（Guardrails & Human-in-the-Loop）
危险操作（写文件/执行命令/外部请求）设置同意闸门与权限分级。MCP 的"工具调用须用户同意"即该模式的协议化。**不变量**：模型输出的每个副作用动作都应有独立于模型的授权来源。

### 7. 上下文工程（Context Engineering）
系统提示/工具定义/历史压缩/检索内容的选择与排布。是提示工程的超集，关注**整个循环中上下文的动态管理**（何时压缩、何时丢弃、何为不可丢弃的锚点）。

## 三、模式选型速查

| 场景 | 首选模式 |
|------|---------|
| 单一明确任务 + 现成工具 | 工具调用循环 |
| 多步骤、可预分解 | 计划-执行 |
| 输出有客观验证器（编译/测试） | 反思循环 |
| 子任务可并行/需上下文隔离 | 编排-工人 |
| 长期运行/跨会话 | 记忆分层 |
| 有副作用的生产系统 | 护栏 + 人工确认（必选） |

## 四、模式不变量（跨框架、跨模型）

1. 循环的终止条件必须显式（步数上限/预算/完成判据），否则 Agent 不收敛
2. 工具粒度：粗工具（一次完成复合操作）优于细工具（模型自行编排多个原子调用）——除非原子编排本身是任务
3. 错误信息是给模型看的：返回可操作的错误（带原因与建议）显著优于失败码
4. 任何"模型知道 X"的假设都要用上下文内容兑现——模型只知道自己能看到的
5. Agent 的可靠性 = 工具可靠性 × 反馈信号质量 × 上下文管理质量；模型能力只是其中一个因子
