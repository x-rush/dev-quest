# 文档写作与验收规范

目标读者会基本编程，但首次接触本技术栈。知识库同时承担全量基础参考、渐进教学、高级解释和框架实践，不用单一种类的模板限制全部内容。

## 先讲清，再补齐

参考词条至少解释：是什么、解决什么问题、何时使用、签名与参数、返回或修改什么、可观察示例、常见误解和边界。关键词解释语法位置与作用域；内置函数解释输入输出和失败语义；标准库解释如何导入、资源由谁关闭、错误由谁处理。速查表可以在前，但不能替代这些解释。

教程在使用概念的位置给出足够完成当前步骤的讲解，再链接完整参考。**单一事实来源约束版本表和完整 API 契约，不禁止教程重复必要的解释。** 读者不应为理解一行代码连续跳转三次。

例如“用依赖注入解耦”信息不足。应写成“把存储对象作为参数传入服务；测试时传入内存存储，就能验证业务规则而不启动数据库”。随后再介绍依赖注入这个名称。

## 拒绝用术语重复代替讲解

“分层架构：清晰的分层结构”“依赖注入：依赖注入模式”“安全配置：安全配置管理”不构成知识解释。给名词添加“统一、严格、高效、合理、完善”等修饰词，也没有告诉读者如何理解和判断。

正文中的建议应交代具体问题、采取的动作、为什么起作用，以及适用条件或代价。例如缓存应解释哪些读取可以复用、允许多久的旧数据、写入后如何失效，而不只写“采用多层缓存策略”。能用一个小例子讲清的地方直接举例；需要代码时交代输入、输出和上下文，不为凑模板强加大段代码。

目录、复习提纲和已有讲解后的检查清单可以简短，但要能定位到实际解释。不能把全文最后的名词清单算成该主题已经覆盖，也不能只在文章开头增加概念提示，却保留正文中未展开的占位讲解。

人工验收可问：第一次见这个术语的人，能否说明它解决的具体问题，并判断一个使用或误用的例子？若只能复述术语，继续补讲解。自动检查只负责标记可疑同义重复，不按字数自动判定质量，不做批量同义改写。

## 按用途验收

| 类型 | 必须具备 | 不应强加 |
|---|---|---|
| 基础教程 | 前置能力、一个明确产物、逐步解释、文件位置、运行方式、预期结果、自测反馈 | 一开始同时接入认证、缓存、消息队列与集群 |
| 参考词条 | 覆盖范围、可检索标题、定义、输入输出、实例、边界、相关入口 | 假装高级知识没有前置门槛 |
| 框架指南 | 要完成的任务、已有工程假设、配置与依赖、关键数据流、验证方法 | 用一长段代码替代职责说明 |
| 高级解释 | 已知知识、具体矛盾、机制、取舍、反例、验证思路 | 没有条件的“必须”“永远”“最佳” |
| 项目练习 | 已学前提、必做与选做、分阶段交付、正常与异常验收、参考思路 | 用缺失实现的草图宣称完整可运行 |

“全量”需要声明集合：例如语言规范的保留关键字是有限集合；第三方包与所有扩展函数不是。对未详细展开的项给出明确外部入口与状态，不以“常用”掩盖目标范围内的遗漏。

## 示例的四种身份

1. **完整示例**：所有必要定义、依赖、文件名和运行入口齐全；不能出现待实现函数。给出预期输出和验证状态。
2. **局部片段**：注明插入哪个文件、依赖哪些先前定义、是否替换已有实现。不可把多个替代方案拼成一份程序。
3. **反例**：写出预期编译错误或行为错误，再给修正思路。不得让学习者把有意错误误认为安装失败。
4. **设计草图**：说明职责与流程，明确哪些实现未展开；不宣称开箱即用。

示例解释应沿输入 → 处理 → 输出推进。注释解释原因和约束，避免逐行复述语法。预期输出不确定时描述可断言性质，例如两个任务都完成，而不承诺并发日志的固定顺序。

## 练习必须有反馈

最小练习至少给出输入、任务、验收结果和提示或参考答案。题目应检查理解而非抄写：修改一个条件、比较两个方案、复现一个边界、定位一条失败路径。

大型项目按“能运行 → 能解释 → 有测试 → 可交付”推进。数据库持久化、并发冲突、身份校验与恢复能力分别验证；标题中出现“生产级”不代表已经具备这些能力。

## 稳定知识与易变知识

语言语义、资源生命周期、状态归属、HTTP 边界等按原理解释。框架 API、安装命令、最低系统版本和工具链兼容性注明适用版本及官方来源。版本表以模块 README 为入口，执行环境以锁文件与实际输出为证据。

不得根据当前年份推算尚未核实的版本，不得把旧的“本机验证”记述当作本轮验证结果。框架的长期价值按解决的问题、维护与兼容策略、迁移成本评估，参见[收录标准](./tech-adoption-checklist.md)。

## 验证要说清边界

- 链接检查只证明目标存在；章节锚点、引用相关性仍要核查。
- 语法检查只证明语法能被解析；缺失依赖、错误行为与教学顺序仍可能存在。
- 运行验证记录版本、命令与结果；平台不可用则写“未运行”，不能把跳过当通过。
- [结构审查工具](../tools/document-quality/README.md)提供人工复核线索，不给文档打伪精确分数。

元数据只保留帮助读者选择的信息：用途、前置、难度和适用范围。不以篇数、字数、图表数或勾选“已完成”作为质量证明。
