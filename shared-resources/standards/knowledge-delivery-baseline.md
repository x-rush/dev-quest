# 知识库交付基线：覆盖、教学与示例验收

适用读者：会变量、条件、循环和函数，但首次接触目标技术栈。适用范围：11 个现行模块及它们依赖的共享语言文档；历史归档不属于当前课程。本基线把[写作规范](documentation-guidelines.md)落实到逐项验收，不以篇数、字数或自动检查通过代替内容质量。

本文件制定验收方法并记录 2026-09-19 的课程结构审查结果；不代表所列模块已经验收完成。后续修补的当前状态以逐项记录和对应示例证据为准。

## 1. 全量覆盖以知识项为单位

模块维护一份覆盖清单，每行记录：知识项、适用版本、前置知识、主讲文件与章节、配套示例、练习或自测、验证证据、未完成项。一个文件可以覆盖多个知识项，但同一个知识项必须有唯一的主讲位置。

| 范围 | 清单如何建立 | 怎样判断已覆盖 |
| --- | --- | --- |
| 语言基础 | 对照基线版本官方规范中的词法、类型、运算符、声明、表达式、语句、作用域和模块规则 | 每项有准确解释、最小实例和适用的边界；不能只出现在目录或速查表 |
| 关键词与内置能力 | 对照基线的保留关键词、预声明标识符或内置函数清单，分别登记 | 名称、语法位置或调用方式、输入输出、限制及误用都可定位 |
| 常用标准库 | 先声明本模块需要处理的任务，再列相应包和核心 API；其余包保留官方导航 | 常用项达到可使用深度；只有一句职责和外链的项标记为“导航”，不计为详解 |
| 框架主线 | 对照真实应用需要的创建、输入、状态、错误、存储、测试和交付流程 | 一条连续路径能够复现，参考条目解释关键 API；非必要扩展不进入初学必修 |
| 高级主题 | 从基础实践中提出具体问题，如取消、争用、缓存失效、性能瓶颈 | 解释机制、成立条件和代价，给可观察实验或有依据的推理 |

“全量基础”不要求穷尽所有第三方包。它要求有限的语言基础集合无遗漏，常用库的选取范围公开，列入范围的内容逐项完成。框架收录继续遵循[价值与维护标准](tech-adoption-checklist.md)。

## 2. 每篇文档的交付字段

这些信息必须存在，但不要求重复堆砌元数据表。短词条可以用一段说明和一个小例子完成；课程章节应形成连贯叙述。

| 字段 | 基础教程必须交代的内容 | 参考条目的对应要求 |
| --- | --- | --- |
| 学习起点 | 开始前能做什么；不会时去哪补齐 | 理解本条所需的类型或概念 |
| 本节产物 | 学完能完成的一个可观察行为 | 本条可以回答的具体问题与覆盖范围 |
| 问题与机制 | 为什么需要它，输入如何经过处理形成输出 | 定义、语法或签名、参数、返回值及副作用 |
| 示例上下文 | 文件、入口、依赖、工作目录和运行命令 | 独立示例或明确关联的完整工程 |
| 预期结果 | 实际输出、状态变化或可断言性质 | 正常值、边界值和失败行为 |
| 关键边界 | 空输入、错误输入、资源生命周期等相关情况 | 限制、常见误解及与相近能力的区别 |
| 练习与反馈 | 一个独立变体，明确输入、任务、验收及提示或答案 | 可用预测输出或辨错题代替小项目 |
| 学习衔接 | 一个明确下一步和必要参考链接 | 关联条目与入门教程入口 |
| 事实与验证 | 易变事实的官方来源；本例实际环境、命令、结论及证据位置 | 同左，不把官方文档链接当作运行证据 |

编辑复核时，让未读过本篇的人回答三个问题：程序接收什么、结果为何如此、改变一个条件会怎样。不能回答时继续补解释；不能要求读者先自行补齐未定义的 `service`、`db` 或辅助函数。

“严格输入验证”“合理缓存”“统一错误处理”等短语只能作为已讲解内容的复习提示。正文必须说明检查什么、由谁检查、失败后发生什么以及为什么采用此方案。

## 3. 示例怎样验收

| 示例身份 | 必须提供的上下文 | 最低有效证据 |
| --- | --- | --- |
| 完整示例 | 全部文件或配套工程、入口、依赖与版本 | 在声明环境中构建或检查，并运行正常和适用的异常路径；结果与正文一致 |
| 局部片段 | 插入的文件、所属完整工程、前置定义、替换还是新增 | 将片段按文档放回工程后验证；只套一个空壳使语法通过不算完成 |
| 反例 | 预期失败的条件、错误性质及修正版本 | 反例按预期失败，修正版通过；编译器措辞变化时核对错误原因 |
| 语法表示或设计草图 | 明确用于解释哪些规则，哪些实现被省略 | 人工核对表达准确性；不计为可运行实现，也不能代替本课必要的完整示例 |

每条验证记录至少关联文档位置、示例身份、源内容哈希、工程文件、工具版本、命令、预期结果、实际结果和结论。文档或依赖改变后重新确认对应证据；不按旧代码块序号沿用成功结果。

语法解析、类型检查、运行行为和教学验收分别记录。缺少工具、平台或服务是未验证；依赖缺失要补上下文；发现真实错误要修正文档。不能通过删除必要例子、虚构第三方 API、扩大忽略清单或改语言标签掩盖失败。纠正本来标错的语言标签仍需保留其实际代码身份。

环境采用已验证版本和项目锁文件。WSL/asdf、容器或原生工具链都可用，但记录实际执行环境；跨环境执行不能推断 Apple SDK、Android 构建或其他平台自动通过。外部服务示例还应交代服务启动、测试数据、清理方法及运行条件。

## 4. 全库共用的渐进路线

每个模块的 `LEARNING_GUIDE.md` 按以下阶段给出实际文章链接、阶段产物与通过条件。阶段是能力顺序，不要求目录重新编号，也不要求按模块编号学完全部技术。

| 阶段 | 产物 | 进入下一阶段前应能做到 |
| --- | --- | --- |
| A 环境与最小程序 | 从空目录启动的程序或界面 | 解释入口，修改输入，复现输出，定位一次启动错误 |
| B 语言与数据 | 普通函数、集合与数据校验 | 说明类型、作用域、值变化和错误路径；完成一个独立变体 |
| C 小型完整应用 | 内存待办、文件统计器或单页交互 | 把输入、验证、状态、输出连起来；有正常、边界和失败验收 |
| D 核心框架 | 单资源 API 或单屏数据应用 | 解释路由、组件或生命周期；能替换一层依赖并保持行为 |
| E 持久化与交付 | 数据保存、测试、打包或部署 | 验证重启、错误和数据边界；在新环境复现安装与运行 |
| F 按需深入 | 一个有明确问题的高级专题 | 解释采用理由、代价及不适用条件，用证据支持改进结论 |

| 模块 | 主线产物顺序 | 需要提前补齐的知识 |
| --- | --- | --- |
| [Go](../../01-go-backend/LEARNING_GUIDE.md) | 函数与错误 → 标准库小工具 → 内存 HTTP API → Gin 与数据库 → 并发及交付 | HTTP 与 JSON 在接入网络前补齐；先理解错误与资源清理，再展开并发 |
| [Next.js](../../02-nextjs-frontend/LEARNING_GUIDE.md) | 静态页面 → React 状态 → 路由与表单 → 服务端数据 → 持久化与部署 | HTML、CSS、JavaScript/TypeScript、HTTP；显式区分浏览器与服务端执行位置 |
| [TanStack](../../03-tanstack-stack/LEARNING_GUIDE.md) | 普通请求 → 查询状态与缓存 → 更新与失效 → 表格或路由专题 | React 组件、Hooks、Promise 与请求失败；各工具按问题引入 |
| [React Native](../../04-multiplatform-apps/LEARNING_GUIDE.md) | 静态界面 → 本地状态 → 导航与请求 → 本地存储 → 设备构建 | JavaScript/TypeScript、React；平台权限与原生能力在实际使用前讲解 |
| [Kotlin / Compose](../../05-kotlin-compose/LEARNING_GUIDE.md) | Kotlin 小程序 → 状态界面 → 生命周期与异步 → 数据层 → Android 构建 | 空安全、函数与集合先于 Compose；协程取消先于复杂并发 |
| [Swift / SwiftUI](../../06-swift-swiftui/LEARNING_GUIDE.md) | Swift 值与函数 → 状态界面 → 导航与异步 → 持久化 → 平台构建 | 可选值、值语义和错误；明确 Apple 平台工具要求 |
| [PHP / Laravel](../../07-php-mastery/LEARNING_GUIDE.md) | PHP 函数与数组 → 请求响应 → Laravel 单资源 → 数据库 → 测试交付 | Composer、HTTP、会话和 SQL 按阶段补齐 |
| [Java / Spring](../../08-java-revisited/LEARNING_GUIDE.md) | 类型与对象 → 集合与异常 → 普通服务测试 → Spring API → 数据库 | 包、构建工具、接口与依赖传入先于注解配置 |
| [Node.js / Hono](../../09-nodejs-backend/LEARNING_GUIDE.md) | JavaScript/TypeScript → 模块与异步 I/O → HTTP → Hono API → 数据库 | Promise、错误传播和模块格式；框架不替代运行时基础 |
| [Python / FastAPI](../../10-python-discovery/LEARNING_GUIDE.md) | 类型与控制流 → 函数与文件 → 小型自动化 → FastAPI → 持久化 | 虚拟环境、异常、模块；类型提示与运行时校验分别解释 |
| [Rust / Tauri / Axum](../../11-rust-cross-platform/LEARNING_GUIDE.md) | 所有权与错误 → 标准库工具 → 测试与异步 → 选择桌面或 API 主线 | 借用、trait 和 Result；Tauri 与 Axum 为应用方向选择，不强制串学 |

| 优先级 | 当前证据与问题 | 修改位置 | 完成条件 |
| --- | --- | --- | --- |
| P0 | README 与导读按编号先并发后错误处理，导读的概念链却先错误后并发 | [README](../../01-go-backend/README.md)、[导读](../../01-go-backend/LEARNING_GUIDE.md)、[错误处理](../../01-go-backend/basics/08-error-handling.md)、[并发入门](../../01-go-backend/basics/07-concurrency-basics.md) | 两个入口与文末导航采用同一能力顺序；无需为排序更改文件名 |

| P1 | 标准库地图明确只提供常用包导航，不能作为所有常用 API 已有详解的证据 | [标准库地图](../../01-go-backend/reference/library-guides/17-std-package-map.md)、[标准库总览](../../01-go-backend/reference/library-guides/01-go-standard-library.md)及对应专篇 | 声明常用 API 清单，逐项关联讲解、例子和练习；导航项与已详解项分开记录 |
| P1 | 编程精华开头 ProcessUsers 的正反例同名且 User 未定义，示例之间的类型与输入输出假设不清 | [编程精华](../../01-go-backend/reference/language-concepts/03-go-programming-essentials.md) | 给明确类型和分别可验证的例子；比较方案先保证需求与结果可比较，再解释取舍 |
| P1 | README 项目目录写 MySQL，REST 项目正文选择 PostgreSQL；介绍与实现不一致 | [README](../../01-go-backend/README.md)、[REST 项目](../../01-go-backend/projects/01-rest-api-server.md) | 确认项目实际依赖，统一目录描述、配置、安装和运行说明 |

修补顺序为：纠正阻断阅读与运行的问题 → 补齐语言参考 → 完成小项目 → 连接框架与数据层 → 验证高级主题。每批完成后同步[文档索引](../tools/document-index.md)和[学习记录入口](../progress/learning-progress.md)，避免正文与学习地图再次分离。

## 6. 完成判据

知识项先完成事实核对和讲解，再完成示例与练习验证，最后核对前置与导航。未完成项要写具体缺口，例如“Android 工程尚未构建”或“copy 的零长度目标边界缺少练习”，不用笼统的“待优化”。

模块交付必须同时满足：声明的基础集合已逐项覆盖、所有必修路径可连续完成、必要示例已在适用环境验证、练习有反馈、已知错误已修复、易变事实有版本依据。语法检查通过但框架未构建的模块只能记录阶段成果，不能标记完整交付。

全库交付要求全部现行模块达到同一标准。措辞中的“零已知错误”仅适用于明确范围、版本和证据对应的内容；不能把尚未审阅或未运行的部分算入这个结论。
