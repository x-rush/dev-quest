## 🔍 核心概念

### 概念一：所有权三规则

**定义**: 所有权（ownership）是 Rust 的编译期内存管理模型——不靠垃圾回收，也不靠手动 free，而是把"资源何时释放"变成编译器可以验证的规则。

**三条规则**:
1. Rust 中每个值都有一个**所有者**（owner）——通常是某个变量
2. 同一时刻，一个值**只能有一个所有者**
3. 所有者离开作用域时，值被**自动释放**（调用 drop）

**与内存管理方案的对比**:

| 方案 | 代表语言 | 释放时机 | 代价 |
|------|---------|---------|------|
| 手动管理 | C / C++ | 程序员决定 | 泄漏与悬垂指针 |
| 垃圾回收 GC | Go / JS / Java | 运行时定期回收 | 运行时开销与停顿 |
| 所有权 | Rust | **编译期确定**（作用域结束） | 学习曲线 |

### 概念二：move 语义与 Copy

**定义**: 把值赋给新变量或传入函数时，默认发生**所有权转移**（move）——原变量从此失效。

**关键特性**:
- 堆上资源（如 `String`、`Vec`）默认 move：转移的是"栈上指针 + 元数据"，堆数据不复制
- 栈上简单类型（整数、浮点、bool、char 等）实现了 `Copy`：赋值按位复制，原变量仍可用
- 需要保留原变量时，用 `clone()` 显式深拷贝——把复制成本写在你眼前

**使用场景**:
- 场景一：函数接管一个资源（如把文件句柄传给消费者）→ 传所有权
- 场景二：只是读一下 → 传借用，避免 move（见概念三）

### 概念三：借用与借用检查器

**定义**: 借用（borrowing）是"临时使用但不接管所有权"的方式：`&T` 为共享借用（只读），`&mut T` 为独占借用（可写）。

**两条核心规则**（借用检查器在编译期强制执行）:
1. 任意时刻，可以有**任意多个不可变借用** `&T`，**或恰好一个可变借用** `&mut T`
2. 不可变借用与可变借用**不可同时存活**

**为什么这么设计**: "多个读者 + 一个写者"并发访问是数据竞争的充分条件。Rust 把这一保证下沉到编译期——不存在的数据竞争比运行时才发现的竞争更安全。

### 概念四：NLL —— 借用到"最后一次使用"为止

**定义**: NLL（Non-Lexical Lifetimes，非词法生命周期）指借用并非存活到作用域结束，而是存活到**最后一次使用**为止。

**关键特性**:
- 现代 Rust 的借用检查基于"使用点"，而不是花括号边界
- 效果：直觉上顺序正确的代码（用完再改）大部分都能直接编译
- 这让"借用检查很烦"的老印象过时——先写自然版本，报错再调整，多数情况下 NLL 已经放行

## 🛠️ 实践指南

### 步骤一：亲手触发一次借用检查错误

**目标**: 建立"编译器是老师不是敌人"的工作方式——读错误信息是学 Rust 的核心技能。

**操作指南**:

```bash
cargo new borrow-lab && cd borrow-lab
```

1. 把下方示例一中被注释的 `println!("{s1}")` 一行取消注释
2. 运行 `cargo check`
3. 阅读报错：`error[E0382]: borrow of moved value: s1`，并注意提示里给出了修复建议
4. 恢复注释，改成 `clone` 版本再 `cargo check`，观察差异

**验证方法**: 能复述出 E0382 报错中"值在哪一行被 move、又在哪一行被使用"两部分信息

### 步骤二：把函数签名改成借用风格

**目标**: 体会"参数优先借用"的惯例。

**操作指南**:
1. 写一个 `fn print_len(s: String)`，调用两次同一个变量——第二次编译失败
2. 把签名改成 `fn print_len(s: &String)`，两次调用都通过
3. 进一步按惯例改为 `fn print_len(s: &str)`（字符串切片，兼容字面量与 String）

**验证方法**: 同一变量能连续传参两次且不 clone

## 💻 代码示例

> 以下四段示例均已在本机以 `rustc --edition 2024` 实测编译并运行通过。

### 示例一：move 语义

```rust
fn main() {
    let s1 = String::from("所有权");
    // s1 的所有权 move 给 s2，此后 s1 失效
    let s2 = s1;
    // println!("{s1}"); // ❌ 编译错误：value borrowed here after move
    println!("{s2}");

    // 整数等实现了 Copy 的类型按位复制，原变量仍可用
    let n1 = 42;
    let n2 = n1;
    println!("n1 = {n1}, n2 = {n2}");

    // 显式 clone 得到深拷贝，两个值各自独立
    let s3 = s2.clone();
    println!("s2 = {s2}, s3 = {s3}");
}
```

**关键点解析**:
- move 转移的是栈上的指针与元数据，堆数据原地不动——所以 move 很便宜
- `Copy` 类型与堆类型的行为差异是初学者最常踩的认知差
- `clone` 是显式成本声明：你在代码里能直接看到"这里发生了深拷贝"

### 示例二：借用与借用规则

```rust
// 计算字符串长度：以借用方式接收，不夺取所有权
fn length(s: &String) -> usize {
    s.len()
}

// 修改需要可变借用
fn push_world(s: &mut String) {
    s.push_str(", world");
}

fn main() {
    let mut s = String::from("hello");

    // 不可变借用可以同时存在多个
    let r1 = &s;
    let r2 = &s;
    println!("{r1} {r2} 长度 = {}", length(&s));
    // r1、r2 在最后一次使用后借用即结束（NLL），此后才能创建可变借用
    let r3 = &mut s;
    r3.push_str("!");
    println!("{r3}");

    push_world(&mut s);
    println!("{s}");
}
```

**关键点解析**:
- 读用 `&`，写用 `&mut`——修改权限被显式建模进函数签名
- 多个只读借用并存是安全的，编译器放行
- `r1`/`r2` 最后一次使用在 `println!` 处，NLL 判定其借用随后结束，所以下一行的 `&mut s` 合法

### 示例三：NLL 让自然代码直接编译

```rust
fn main() {
    let mut scores = vec![90, 85, 77];

    // 不可变借用：读取第一个元素
    let first = &scores[0];
    println!("第一项 = {first}");
    // first 在上一行之后不再使用，借用随之结束（NLL）

    // 因此这里创建可变借用是允许的
    scores.push(100);
    println!("现在共 {} 项", scores.len());

    // 反例（取消注释将编译失败）：
    // let x = &scores;           // ❌ 不可变借用还活着
    // scores.push(100);          // ❌ 与 push 的可变借用冲突
    // println!("{x:?}");
}
```

**关键点解析**:
- `first` 用完后借用即结束，`push` 的可变借用不再与之冲突——这是 NLL 的典型收益
- 反例中 `x` 在 `push` 之后还要使用，借用必须活到那时，编译器正确拒绝（E0502）

### 示例四：所有权与借用的函数边界

```rust
// 返回所有权：最简单、最不容易出错的方式
fn make_greeting(name: &str) -> String {
    format!("你好，{name}！")
}

// 返回借用：借用生命周期与输入绑定（此处省略标注，由编译器推断）
fn longest_word(sentence: &str) -> &str {
    sentence.split_whitespace().next().unwrap_or("")
}

fn main() {
    let text = "rust 跨平台 一把梭";
    let word = longest_word(text);
    println!("第一个词: {word}");

    let greeting = make_greeting("rustacean");
    println!("{greeting}");
}
```

**关键点解析**:
- 参数用 `&str` 而不是 `String`：借用让调用方保留所有权，`&str` 还能同时接收字面量
- 返回新建值 → 返回所有权；返回输入的一部分 → 返回借用（生命周期与输入绑定，深入的标注规则见后续生命周期篇）
- 拿不准时优先"返回所有权"——永远编译通过，代价只是可能多一次拷贝

## 🎨 最佳实践

### ✅ 推荐做法
- **函数参数优先借用**: 用 `&str` / `&[T]` / `&T` 而不是 `String` / `Vec<T>` / `T`，把选择权留给调用方
- **clone 当作显式成本声明**: 需要独立副本就写 clone，成本可见、可审计，好过绕弯的引用技巧
- **先写自然的顺序代码**: 信任 NLL，报错时再阅读借用冲突点并调整持有时序

### ❌ 避免陷阱
- **为绕过检查到处 clone**: 治标不治本，正确解法往往是重构数据的持有关系（谁真正拥有它）
- **在循环中长期持有可变借用**: 典型解法是"先收集要改的索引，循环结束后再统一改"
- **用 unsafe 绕过借用检查**: 那不是绕过，是放弃编译期保护，basics 阶段禁止触碰

## ❓ 常见问题

### Q1: 为什么可变借用和不可变借用不能同时存在？
**A**: 数据竞争的经典形态是"一些读者在读取的同时写者在修改"。Rust 在编译期强制读写互斥，从根源上消灭这类竞争。想要"多处共享 + 内部可变"时，标准库提供了 `RefCell`、`RwLock` 等把检查搬到运行时的类型（后续智能指针篇详解）。

### Q2: 报 `value borrowed here after move`（E0382）怎么改？
**A**: 三选一：① 确实需要副本 → `clone()`；② 只是需要访问 → 改传引用 `&s`；③ 所有权设计错了 → 调整数据流向，让唯一所有者负责整段生命周期。先读错误信息里"move 发生行"与"使用行"两个位置再动手。

### Q3: Rust 没有 GC，会不会内存泄漏？
**A**: 所有权防的是 use-after-free、悬垂指针、数据竞争这类**内存不安全**问题。内存泄漏（如引用计数成环）在 Rust 里属于安全行为，不会引发未定义错误；需要防泄漏时用 `Rc::weak` 等手段（后续智能指针篇）。

## 📝 总结

### 核心要点回顾
1. **三规则**: 值有唯一所有者；赋值/传参默认 move；作用域结束自动释放
2. **借用二分**: 多个 `&T` 或一个 `&mut T`，读写互斥在编译期强制
3. **NLL**: 借用存活到最后一次使用，自然顺序的代码大多直接编译
4. **修复套路**: clone / 改借用 / 重构所有权流向，三选一
