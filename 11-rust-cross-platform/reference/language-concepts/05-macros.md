# 宏系统

## 概述

Rust 宏是**编译期代码生成**机制：在类型检查与代码生成之前，把匹配到的 token 树替换为新的 token 树。两大分支——**声明宏**（`macro_rules!`，按模式匹配 token 的小语言）与**过程宏**（操作 `TokenStream` 的编译期 Rust 程序）。宏属语言稳定层（基线 Rust 1.98.1 / edition 2024，见[模块 README](../../README.md)），本篇按字典条目组织，供跳入查阅。

## 条目 1：宏两大家族总览

📌 **定义**: 宏在**编译期**接收 token 树、展开为新代码，先于类型检查运行。声明宏用"匹配器 + 模板"描述模式；过程宏是完整的编译期程序。除派生宏/属性宏外，宏调用都以 `!` 结尾。

📖 **家族对照**:

| 家族 | 定义位置 | 输入 | 典型用途 | 生态示例 |
|------|---------|------|---------|---------|
| 声明宏 `macro_rules!` | 同 crate 内（或经 `#[macro_export]` 导出） | token 树模式 | 集合构造、断言、格式化 | `vec!` `assert_eq!` `println!` |
| 过程宏 · 派生 `#[derive(X)]` | 独立 crate（`proc-macro = true`） | 附着的类型定义 | 给类型生成 impl | serde `Serialize`、clap `Parser` |
| 过程宏 · 属性 `#[attr(...)]` | 同上 | 修饰的 item + 参数 | 改写/注解 item | `#[tokio::main]` |
| 过程宏 · 函数式 `x!(...)` | 同上 | 任意 token 树 | DSL | sqlx `query!` |

**常用标准库声明宏速查**:

| 宏 | 用途 | 宏 | 用途 |
|----|------|----|------|
| `println!` `format!` `write!` | 格式化输出/拼接 | `assert!` `assert_eq!` `assert_ne!` | 断言（失败即 panic） |
| `vec!` | Vec 字面量构造 | `dbg!` | 打印表达式及值并原样返回 |
| `matches!` | 表达式是否匹配某模式 | `cfg!` | 编译期条件为 bool |
| `panic!` `todo!` `unimplemented!` | 终止/占位 | `concat!` `stringify!` | 字面量拼接/源码文本化 |
| `env!` `include_str!` `include_bytes!` | 编译期取环境变量/嵌入文件 | `thread_local!` | 线程局部存储 |

⚠️ **常见陷阱**: 过程宏必须放在声明 `proc-macro = true` 的**独立 crate**，不能与使用方同 crate；声明宏无此限制。宏展开发生在类型检查**之前**，所以宏报错常常面目全非——先展开再读。

🔗 **相关条目**: [条目 6：过程宏三类型概览](#条目-6过程宏三类型概览)

## 条目 2：匹配器类型表

📌 **定义**: `macro_rules!` 每条臂形如 `($模式) => {$模板};`，模式由**匹配器**（`$name:kind`）与字面 token 组成；宏按**声明顺序**逐臂尝试匹配，首个匹配者生效。

📖 **匹配器全表**:

| 匹配器 | 匹配内容 | 示例输入 |
|--------|---------|---------|
| `expr` | 表达式 | `1 + 2`、`f(x)` |
| `ident` | 标识符/关键字 | `foo`、`self`、`u32` |
| `tt` | 单个语法树（单 token 或括号组） | `+`、`(a b)` |
| `literal` | 字面量 | `42`、`"str"`、`'c'` |
| `ty` | 类型 | `Vec<u8>`、`&str` |
| `pat` | 模式（match 分支左侧） | `Some(x)`、`1..=9` |
| `path` | 路径 | `std::mem`、`Option::None` |
| `stmt` | 语句 | `let x = 1;` |
| `block` | 块表达式 | `{ ... }` |
| `item` | 项（fn/struct/impl…） | `fn f() {}` |
| `vis` | 可见性限定（可为空） | `pub`、`pub(crate)`、空 |
| `lifetime` | 生命周期 | `'a` |
| `meta` | 属性体（括号内内容） | `derive(Debug)` |

⚠️ **常见陷阱**: `expr` 等"不可再细分"的匹配器之后只允许跟 `=>`、`,`、`;` 这类终结 token（**follow set** 限制），直接跟 `ty` 会报 ambiguous——需要继续加工时改用 `tt` 自己消化；`ident` 会连关键字一起匹配，模板中直接可用。

🔗 **相关条目**: [条目 3：重复语法](#条目-3重复语法)

## 条目 3：重复语法

📌 **定义**: `$(...)分隔符重复符` 是声明宏处理变长输入的核心：捕获部分重复出现，模板里写同样形状的重复即可逐个展开。

📖 **语法/签名**:

| 写法 | 含义 |
|------|------|
| `$(...),*` | 零次或多次，逗号分隔 |
| `$(...)+` | 一次或多次（至少一个） |
| `$(...)?` | 至多一次（可选） |
| `$(...);*` | 分隔符可换成任意单 token（`;` `\|` 等） |
| `$(,)?` | 惯用法：容忍调用方尾随逗号 |

💡 **示例**（本块经 rustc edition 2024 实测通过）:

```rust
// 匹配器类型 + 重复语法 + 宏生成 item
macro_rules! make_shout {
    ($name:ident, $word:literal) => {
        struct $name;
        impl $name {
            fn shout(&self) -> &'static str {
                $word
            }
        }
    };
}
make_shout!(Dog, "汪汪");

// 重复语法：$first 必给，$rest 零或多个，容忍尾随逗号
macro_rules! max_of {
    ($first:expr $(, $rest:expr)* $(,)?) => {{
        let mut acc = $first;
        $(
            if $rest > acc {
                acc = $rest;
            }
        )*
        acc
    }};
}

fn main() {
    let d = Dog;
    println!("{}", d.shout());
    println!("{}", max_of!(3));
    println!("{}", max_of!(3, 9, 2,));
    println!("{}", max_of!(-1.5, -2.5, -0.5));
}
```

**关键点解析**:
- `make_shout!` 在 **item 位置**展开，一次生成 struct + impl——宏可出现在任何语法位置（表达式/语句/item/模式）。
- `max_of!` 用 `$first + $(, $rest)*` 拆出"至少一个参数"：空输入直接编译失败，错误早于运行时。
- `$(,)?` 使 `max_of!(3, 9, 2,)` 的尾随逗号合法。
- `{{ }}`：外层 `{}` 是宏臂模板定界，内层 `{}` 是块表达式，使宏能声明局部变量并返回值。

⚠️ **常见陷阱**: 嵌套重复时 metavariable 必须"维度对齐"——内层重复只能引用内层捕获的变量；`*` 与 `+` 选错会错误地接受/拒绝空参数列表。

🔗 **相关条目**: [条目 4：递归宏](#条目-4递归宏)

## 条目 4：递归宏

📌 **定义**: 宏模板中可再次调用宏自身，以"每次剥掉一个参数"的方式推进，必须提供**终止臂**。重复语法 `$(...)*` 一次展开到底；递归宏适合需要**逐个累积/嵌套构造**的场景。

📖 **语法/签名**: 臂按声明顺序匹配——终止臂写在递归臂**之前**（`()` 在前，`$head, ...` 在后），否则空输入落入递归臂导致无限展开。

💡 **示例**（与条目 5 共用一块，经 rustc edition 2024 实测通过）:

```rust
#![allow(unused_variables)]

// 递归宏：列表求和（$head 逐个剥离）
macro_rules! sum_all {
    () => { 0 };
    ($head:expr $(, $tail:expr)*) => {
        $head + sum_all!($($tail),*)
    };
}

// 宏卫生：宏内部的 x 与调用处的 x 是不同符号
macro_rules! shadow_demo {
    () => {
        let x = 999; // 宏内部引入的 x
    };
}

fn main() {
    println!("{}", sum_all!(1, 2, 3, 4)); // 10
    let x = 1;
    shadow_demo!();
    println!("调用处的 x = {x}"); // 1，未被宏污染
}
```

**关键点解析**:
- `sum_all!(1, 2, 3, 4)` 展开为 `1 + sum_all!(2, 3, 4)` → … → `4 + sum_all!()` → `4 + 0`。
- 进阶写法 **tt muncher**：以 `tt` 匹配逐 token 消化输入、维护累积状态，是 `macro_rules!` 的图灵机式用法；解析复杂到这个程度就该转过程宏。

⚠️ **常见陷阱**: 臂顺序错误会把终止臂永久遮蔽；递归展开无显式深度上限，但超过编译器限制会报错——报错信息不会指向"递归层数"。

🔗 **相关条目**: [条目 3：重复语法](#条目-3重复语法)、[条目 5：宏卫生](#条目-5宏卫生)

## 条目 5：宏卫生（hygiene）

📌 **定义**: `macro_rules!` 是**混合卫生**：宏内引入的**局部变量与 label** 在定义点解析——与调用处同名标识符是不同符号，宏不会意外捕获也不会污染调用方变量；**item、生命周期等**在调用点解析，宏生成的 item 遵循正常可见性规则。

📖 **语法/签名**: 无专门语法，卫生是展开器行为。需要"借用调用处标识符"时，把它作为 `$name:ident` 参数显式传入。

💡 **示例**: 见条目 4 代码块的 `shadow_demo!`——宏内的 `let x = 999;` 是全新的 `x`，`main` 的 `x` 保持为 1。

⚠️ **常见陷阱**: 想复用调用处变量必须传参（`$v:ident`），依赖同名捕获是可移植性错误；库宏引用自身 crate 的路径一律用 `$crate`（定义点解析），写死 `::crate_name` 在使用者重命名依赖后失效。

🔗 **相关条目**: [条目 7：导出与调试](#条目-7导出与调试)

## 条目 6：过程宏三类型概览

📌 **定义**: 过程宏是**编译期运行、操作 `TokenStream` 的 Rust 程序**，必须位于声明 `proc-macro = true` 的独立 crate，只能导出宏这一种符号。三种形态对应三种接入位置。

📖 **三类型对照**:

| 类型 | 调用形态 | 输入 | 输出 |
|------|---------|------|------|
| 派生宏 derive | `#[derive(MyDerive)]` | 附着类型定义的 TokenStream | 追加在该 item 之后的 TokenStream（通常是 impl） |
| 属性宏 | `#[my_attr(arg)]` | 修饰的 item + 属性参数 | **完全替换**该 item |
| 函数式宏 | `my_fn!(tokens)` | 调用处 token 树 | 替换调用处 |

💡 **使用侧示例**（本块经 rustc edition 2024 实测通过；derive 是过程宏最常见入口）:

```rust
#[derive(Debug, Clone, PartialEq)]
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let a = Point { x: 1, y: 2 };
    let b = a.clone();
    println!("{:?} 相等: {}", a, a == b); // Point { x: 1, y: 2 } 相等: true
}
```

**关键点解析**:
- 派生宏可定义**辅助属性**（如 serde 的 `#[serde(rename = "...")]`），解析规则由宏实现者规定。
- 过程宏生态三件套：`syn`（TokenStream → 语法树）、`quote`（语法树 → TokenStream）、`proc-macro2`（与编译器接口的互操作层）——工程上几乎必用，属第三方 crate。
- 实现侧报错用 `syn::Error` 转 `compile_error!` 输出，保留用户源码位置（span），否则报错不可读。

⚠️ **常见陷阱**: 属性宏是**替换**不是包裹——忘了原样重组输入会静默吞掉 item；过程宏展开结果不可见，调试靠 `cargo expand`（第三方子命令）看展开后代码。

🔗 **相关条目**: [条目 1：宏两大家族总览](#条目-1宏两大家族总览)

## 条目 7：导出与调试

📌 **定义**: 声明宏用 `#[macro_export]` 导出到 crate 根，使用者可 `use my_crate::my_macro;` 路径导入；同 crate 内**未导出**的宏遵循文本顺序——必须先定义后使用（宏不像普通 item 可以乱序）。

📖 **语法/签名**（示意，非可运行块）:

```rust
#[macro_export]
macro_rules! my_vec { /* ... */ }

// 使用方 crate：
// use my_crate::my_vec;
// let v = my_vec![1, 2, 3];
```

| 工具 | 用途 | 备注 |
|------|------|------|
| `cargo expand` | 打印宏展开后源码 | 第三方子命令，宏调试主力 |
| `rustc --explain <错误码>` | 解释展开相关错误 | 编译器错误自带展开位置标注 |
| `///` 文档注释写在定义上 | IDE 悬浮展示 | 与普通 item 一致 |

⚠️ **常见陷阱**: `#[macro_export]` 的宏永远挂在 crate 根，与定义所在模块无关；旧式 `#[macro_use] extern crate` 文本作用域导入仍存在，但优先用路径导入；`macro_rules!` 定义在函数体内也能用——作用域即该文本区域，常用于局部 DSL。
