## 📌 一、三条基本规则

**定义**: 所有权与借用检查主要在编译期约束值的使用和释放；析构、分配、引用计数等仍可能有运行时成本。

1. Rust 中每个值都有**唯一所有者**（owner）。
2. 任一时刻，值要么有任意多个共享借用（`&T`），要么恰好一个可变借用（`&mut T`）——二者不可并存。
3. 所有者离开作用域，值被 **drop**（析构函数 `Drop::drop` 运行，内存释放）。

| 术语 | 含义 |
|------|------|
| move | 所有权的转移；原变量进入"未初始化"状态 |
| Copy | 赋值/传参时的隐式位复制（不转移所有权） |
| borrow | 通过 `&T` / `&mut T` 临时访问值而不取得所有权 |
| drop | 所有者析构：`Drop::drop` → 逐字段 drop → 释放内存 |

## 📌 二、Move 语义表

赋值（`let b = a;`）、按值传参、按值返回共用同一套判定——下表以赋值为代表。

| 类型 / 情形 | `let b = a;` 之后 | 依据 |
|------|------|------|
| `i32` / `u64` / `f64` / `bool` / `char` 等标量 | `a` 仍可用（位复制） | `Copy` |
| `&T`（共享引用本身） | `a` 仍可用 | `Copy` |
| `&mut T`（可变引用本身） | 非 Copy；可发生 move 或按上下文重新借用 | 独占访问约束 |
| 函数指针、裸指针 `*const` / `*mut` | `a` 仍可用 | `Copy` |
| 数组 `[T; N]` | `T: Copy` 时逐元素复制，否则整体移动 | 逐元素 |
| 元组 `(A, B)` | A、B 均 `Copy` 时复制 | 逐成员 |
| `String` / `Vec<T>` / `Box<T>` / `HashMap` | `a` 失效，再用报 E0382 | move |
| 自定义 struct / enum 未实现 `Copy` | move（默认，编译器**不会**自动实现） | move |
| 闭包 | 按捕获方式；捕获值全为 `Copy` 时闭包才可 `Copy` | 捕获 |

**关键语义**:

- move 后原变量处于未初始化状态：直接再读报 E0382；**重新赋值可复活**（`s = String::from("x");` 合法，之后 `s` 正常使用）。
- 编译器不隐式深拷贝任何堆数据；需要副本必须显式 `.clone()`。
- `if` / `match` 分支间按值移动同一变量是合法的（每条路径各自移动一次）。

## 📌 三、Copy 与 Clone

| | `Copy` | `Clone` |
|------|------|------|
| 触发方式 | 赋值 / 传参 / 返回时**隐式**位复制 | 只能显式 `.clone()` |
| trait 关系 | 是 `Clone` 的子 trait（`Copy: Clone`） | 可单独实现 |
| 代价约定 | 按位复制，约定廉价 | 任意代价（`String::clone` 深拷贝；`Arc::clone` 仅计数 +1） |
| 与 `Drop` 的关系 | **互斥**：实现 `Drop` 的类型禁止实现 `Copy`（编译器拒绝，防二次析构） | 可与 `Drop` 共存 |
| derive 条件 | 所有字段均为 `Copy` | 所有字段均为 `Clone` |

**要点**:

- 自定义类型不会自动获得 `Copy`；`#[derive(Copy, Clone)]` 是显式 opt-in。
- 实现 `Copy` 必须同时提供 `Clone`，且 `clone()` 的结果必须与位复制一致。
- 共享指针惯例：`Arc` 场景写 `Arc::clone(&x)` 而非 `x.clone()`，让"廉价复制"意图在代码里显式可见。
- `derive(Copy)` 不是零成本的——大数组 `Copy` 有实际复制开销，且会削弱 move 检查对"意外使用原值"的保护。

## 📌 四、借用规则矩阵

前提：目标位置必须允许可变访问；通过已有 &mut T 也能修改所指值，引用变量本身不一定需要 mut。借用存活期见下一节 NLL。

| 已有借用 ↓ ＼ 新操作 → | 再取 `&T` | 再取 `&mut T` | 按值使用 / 移动原值 |
|------|------|------|------|
| 多个 `&T` 共存中 | ✅ | ❌ E0502 | ❌ E0505 |
| 一个 `&mut T` 存活中 | ❌ E0502 | ❌ E0499 | ❌ E0505 |
| 无存活借用 | ✅ | ✅ | ✅ |

**补充规则**:

- 借用的存活期不得超出被借值的存在期（E0597，生命周期视角见[高级生命周期](./04-advanced-lifetimes.md)）。
- 不同**字段路径**可分别借用：`&a.f1` 与 `&mut a.f2` 可共存——借用检查按字段路径拆分，不是整个值一刀切。
- `&mut T` 传参时编译器自动 **reborrow**（等价 `&mut *r`）：调用结束后原借用 `r` 仍可用。
- `v[0]` 索引产生的临时引用受整体借用约束——"迭代中修改容器"是 E0502 的头号来源。

## 📌 五、NLL：借用区间 = 创建点到最后使用点

现行借用检查器沿控制流计算借用存活区间——从创建点到最后一次使用的点，而非包裹它的词法块（NLL，non-lexical lifetimes）。

| 写法 | 判定 |
|------|------|
| `let len = v.len(); v.push(x);` | ✅ `len` 的借用在其最后使用点已结束 |
| `let r1=&v; let r2=&v; use(r1,r2); let w=&mut v;` | ✅ 共享借用使用完毕后才取独占借用 |
| `let r=&v; let w=&mut v; use(r);` | ❌ `r` 在独占借用之后仍被使用，区间重叠 |

保守延长：被借类型实现 `Drop` 时，部分场景下借用被保守延长到作用域结束（防止析构函数观察到失效数据）。

## 📌 六、Drop 顺序

下表区分语言保证与不应依赖的实现观察：

| 对象 | 顺序 | 实测 |
|------|------|------|
| 同一作用域多个局部变量 | 声明的**逆序**（后声明先 drop） | ✅ |
| 嵌套块 | 内层变量先于外层 | ✅ |
| 实现 `Drop` 的 struct | 先执行自身 `Drop::drop`，再按**声明顺序** drop 各字段 | ✅ |
| `Vec` 元素 | 标准库不保证元素析构顺序，不得依赖某次观察 | 不作顺序承诺 |
| 循环 | 每轮迭代结束时 drop 本轮绑定与临时值 | — |
| 表达式临时值 | 通常在语句末尾；`match` 的 scrutinee 临时值存活到整个 `match` 结束 | — |
| 手动提前释放 | `drop(x)`（即 `std::mem::drop`，按值接手立即析构） | — |

## 📌 七、部分移动与字段级借用

- `let name = p.name;` —— 单字段移动：`p.name` 失效，其余字段可用，但 `p` 不能再整体按值使用（E0382）。
- 实现 `Drop` 的类型禁止字段级移动（E0509）。
- 不移动整个值的前提下取走字段：`std::mem::replace(&mut p.field, new)`、`Option::take()`。
- 字段级借用互不影响（见第四节补充规则）。

## 📌 八、错误码速查表

| 错误码 | 含义 | 典型触发 | 修复方向 |
|------|------|------|------|
| `E0382` | 使用已移动的值 | move 后继续读原变量 | `clone()` / 改传引用 / 重新赋值复活 |
| `E0502` | 可变借用与已有借用冲突 | 迭代 `&v` 时 `v.push(..)` | 缩小借用区间 / 先复制所需数据 |
| `E0499` | 第二个可变借用 | 同时存在两个 `&mut` | 拆分作用域 / 先用完再借 |
| `E0505` | 值被借用期间被移动 | 先 `&v` 再 move `v` | 调整顺序 / `clone()` |
| `E0507` | 从借用内容中移出值 | `match &opt` 分支中把 `*v` 按值用 | 按值 `match` / `.as_ref()` / `clone()` |
| `E0509` | 移出实现 `Drop` 的类型的字段 | 解构带 `Drop` 的 struct | 逐字段访问 / 重新设计 `Drop` |
| `E0597` | 被借值活得不够久 | 局部值借给更长命的结构 | 拉长被借值作用域 / 返回 owned |
| `E0106` | 缺少生命周期标注 | 返回引用但签名无法推断 | 显式 `<'a>` 关联（见[高级生命周期](./04-advanced-lifetimes.md)） |

## 💡 可运行示例

### 示例一：move / clone / copy 三分法

```rust
fn main() {
    // Move：非 Copy 类型的赋值转移所有权
    let a = String::from("dev");
    let b = a; // a 的所有权移入 b，此后 a 失效
    println!("{b}");

    // Clone：显式深拷贝，原值仍可用
    let c = b.clone();
    println!("{b} / {c}");

    // Copy：标量类型按位复制，原值不受影响
    let n1: i32 = 42;
    let n2 = n1;
    println!("{n1} {n2}");
}
```

输出：`dev` → `dev / dev` → `42 42`。预期结果。

### 示例二：NLL 让"顺序借用"合法

```rust
fn main() {
    let mut buf = String::from("ab");
    let len = buf.len(); // 共享借用，最后一次使用就在本行
    buf.push('c'); // ✅ 前一借用已过"最后使用点"，允许再次借用
    let r1 = &buf;
    let r2 = &buf; // ✅ 多个共享借用共存
    println!("{r1} {r2}");
    let w = &mut buf; // ✅ r1/r2 此后不再使用
    w.push('d');
    println!("{len} {buf}");
}
```

输出：`abc abc` → `2 abcd`。预期结果。

### 示例三：drop 顺序实证

```rust
struct Probe(&'static str);
impl Drop for Probe {
    fn drop(&mut self) {
        println!("drop {}", self.0);
    }
}

struct Pair {
    first: Probe,
    second: Probe,
}
impl Drop for Pair {
    fn drop(&mut self) {
        println!("drop Pair（自身 Drop 先执行）");
    }
}

fn main() {
    let _a = Probe("a（先声明）");
    let _b = Probe("b（后声明）");
    {
        let _inner = Probe("inner（内层块）");
        println!("-- 内层块结束 --");
    }
    let _p = Pair {
        first: Probe("字段 first"),
        second: Probe("字段 second"),
    };
}
```

预期输出顺序：内层块结束 → `inner` → `Pair`（自身 Drop）→ 字段 first → 字段 second → `b` → `a`——演示局部变量与结构体字段的顺序；该程序没有验证 Vec 元素析构顺序。

## ⚠️ 编译失败演示

**以下两块为编译失败演示，错误码预期结果复核**（rustc，edition 2024）。

E0382：使用已移动的值。

```rust
fn main() {
    let s = String::from("dev");
    let t = s; // 所有权移入 t
    println!("{s} {t}"); // s 已被移动，仍使用 → 错误
}
```

预期诊断：`error[E0382]: borrow of moved value: 's'`。

E0502：可变借用与共享借用冲突。

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let first = &v[0];
    v.push(4); // 需要独占借用，first 尚未结束使用
    println!("{first}");
}
```

预期诊断：`error[E0502]: cannot borrow 'v' as mutable because it is also borrowed as immutable`。

## ⚠️ 常见陷阱

- ❌ **迭代集合的同时修改它**（`for x in &v { v.push(..) }` → E0502）。
  - ✅ 先收集要改动的信息再统一修改，或改用索引循环、保留可变借用的 API。
- ❌ **以为 move 后变量"已销毁"不能再赋值**。
  - ✅ 变量回到未初始化状态，重新赋值即复活；"先声明、分支中分别赋值"是惯用法。
- ❌ **在 `match &opt` 中按值使用 `*v`**（E0507）。
  - ✅ 按值 `match opt { Some(v) => .. }`，或 `.as_ref()` 保持引用视角，或 `clone()`。
- ❌ **给所有结构体顺手 `derive(Copy)`**。
  - ✅ Copy 扩大隐式复制、削弱 move 保护；仅对小型廉价值（坐标、ID、句柄）使用。
- ❌ **手动实现 Clone 与 Copy 语义不一致**（`clone()` 深拷贝但 `Copy` 位复制）。
  - ✅ 实现 `Copy` 时 `clone()` 必须退化为位复制（通常两个一起 derive）。
- ❌ **靠重排语句"绕过"借用检查而不理解 NLL**。
  - ✅ 心智模型：借用区间 = 创建到最后一次使用；把使用点收拢即可共存。

## 先追踪谁拥有值，再考虑是否需要复制

前置是变量、作用域与函数参数。String 的 move 转移管理堆缓冲区的值，不等于把堆里每个字符重新复制一遍；clone 才显式请求副本。&String 借用访问同一份字符串，&mut String 提供独占修改权限。&mut T 本身不是 Copy，函数调用中原引用仍可继续使用往往来自重新借用，不能据此推导可变引用可以随意复制。

借用检查拒绝代码时，先明确数据流：调用者还需要所有权吗，函数只是读取还是确实要保存数据，引用是否跨越修改点。只读参数常选 &str 或 &[T]，返回独立数据才考虑 owned 值；不要用到处 clone 掩盖所有权设计。生命周期标注描述引用之间的关系，不能延长局部变量实际存在的时间。

练习：把 String 传给只接收 &str 的长度函数，调用后仍可打印原值；改为按值接收 String 后，再次打印应产生移动错误。再为 Vec 元素创建引用，尝试 push 后继续用该引用，解释扩容可能使地址失效。最后用 split_at_mut 同时修改互不重叠的两段切片，理解安全 API 如何向编译器表达“不相交”，而不是绕过借用规则。

## 📝 要点回顾

1. **move 与 Copy 由类型决定**：标量/共享引用/函数指针通常 Copy，可变引用不 Copy，堆容器与未声明 Copy 的自定义类型 move。
2. **Copy ⊂ Clone，且与 Drop 互斥**；自定义类型不自动 Copy。
3. **借用矩阵一句话**：多个 `&T` 或恰好一个 `&mut T`；借用区间 = 创建到最后使用（NLL）。
4. **drop 顺序**：局部变量逆序，struct 先自身后字段（声明序），Vec 元素析构顺序不保证。
5. **修错三板斧**：`clone()`、缩小借用区间、调整语句顺序——按错误码速查表定位即可。
